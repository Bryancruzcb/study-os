I grade my own answers. Then I check the grader.

Study OS turns a lecture PDF into questions cited to their source pages, grades my short answers against a rubric, and records every time I overrule the grader. That rate is the number it publishes about itself.

How it works

Three steps. The third one is the interesting one.

01

Ingest

A lecture PDF goes to Claude as a document block under a structured-output schema. Back come concepts and questions, asked to cite the pages they were drawn from. A file already ingested is recognised by its content hash and never paid for twice. A failed extraction is retried once, then marked failed, so there are no silent partial ingests.

02

Study

Concepts are scheduled with SM-2-lite spaced repetition. A correct answer multiplies the interval by the ease and always adds at least a day; a miss resets the interval to one day and drops the ease by 0.2, with a floor of 1.3. The dashboard shows what is due and how each concept is actually going.

03

Grade, and overrule

A short answer gets one grader call against that question's rubric. I can overrule the grader on my most recent answer, and every one of those corrections is recorded. They become the dataset that measures the grader. If the grader call fails there is no verdict to overrule, so the attempt waits for me to grade it myself rather than blocking the session.

What it measures about itself

I hand-label questions on three checks and the app reports the share that pass each one. It reports its own grader the same way.

  • 100%Answerable from source
  • 97%Correct answer
  • 94%Unambiguous
  • 100% n=1 Grader agreement

The three label rates cover 31 questions. The grader agreement covers one graded short answer, so it means “no disagreement yet” rather than “the grader is right”. The app reports the sample size beside it; the flag is on this page, and it stays until there is a real sample behind it.

The rest of it

How it is built

A Spring Boot API over Postgres, a React and TypeScript frontend, and the Anthropic Claude API for both generation and grading.

  • Java 21
  • Spring Boot
  • PostgreSQL
  • React 19
  • TypeScript
  • Vite
  • Anthropic Claude API
  • Docker Compose
  • GitHub Actions

Continuous integration runs three jobs on every pull request and on pushes to the main branches: the backend suite, a JPA suite against a real Postgres service container, and the frontend. The default backend and frontend suites are hermetic, needing neither a database nor an API key.

What it is not

  • This is v1 and it is built for exactly one person. There are no accounts and no auth, so anyone who can reach the port can use it.
  • It runs on a laptop. Nothing is deployed: the source and this page are the only parts of it on the internet.
  • Ingest is one call per file with no progress and no background queue, so a long deck takes a while and the upload request waits for it.
  • Uploads have to be PDFs and nothing checks that, so anything else simply fails to ingest. Files are capped at 32 MB.
